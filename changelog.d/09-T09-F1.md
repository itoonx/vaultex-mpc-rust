- **Transport: the NATS mTLS connect now enforces TLS.** `NatsTransport::connect_signed_tls` accepts only `tls://` URLs and refuses every other scheme before it reads the key or opens a socket. It requires TLS on every connection, reconnects included, whatever the server's INFO says, and never dials server addresses the cluster advertises. The client-key PEM buffer is now zeroized on every path, errors included. New tests: a non-`tls://` URL is refused with no connection attempt; against a fake plaintext server the client opens a TLS handshake and never sends CONNECT in plaintext; the PEM loader accepts PKCS#8 and SEC1 EC keys and a PKCS#1 RSA key whose public half matches the client certificate, and names a key file that holds no key. The fixtures are throwaway test material from a test-only CA (`crates/mpc-wallet-core/tests/fixtures/nats-tls-test-only/`). Services do not call this function yet; bus TLS is still to be wired.
