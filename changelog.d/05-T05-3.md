- **Verifier kernel: policy bundle v1.** `vaultex-verify` now reads a quorum-signed policy bundle that each signer installs as a file of its own (ADR-11; there is no remote governance service). The body is BCS with a tagged SHA-256 digest (`VAULTEX/POLICY-BUNDLE/v1`), signed with strict Ed25519 by pinned admin keys; a signature counts only if its key is pinned, and each key counts once. The admin set and threshold that judge a new bundle come from the bundle in force, or from the genesis pin for the first one. Versions must strictly increase. A bundle that is provably tighter, field by field (the table is in the module docs), needs one admin signature and takes effect at once; anything else needs M-of-N and takes effect only after a time lock counted from when this signer recorded receiving it. A policy that allows transfers with no approval must say so and always needs M-of-N. The bundle pins each wallet's network, address and permission id, and each asset's token contract, decimals, per-transfer cap (U256), recipients, approval tiers and velocity windows; anything it does not list is refused. It supplies the TRON decoder's allowlist and bounds. The installed file is replaced atomically and durably, locked while open, and re-checked on load. Draft vectors live in `crates/vaultex-verify/vectors/POLICY_BUNDLE_V1/` (112 sequences). **They are regression vectors produced with the kernel's own encoder, not external evidence:** the independent JS oracle that must reproduce them comes with the `POLICY_BUNDLE_V1` RFC draft and the adversarial program. The one external check so far is RFC 8032 §7.1 through the same Ed25519 entry point.
